SecureCloud Architecture

Encrypted Cloud Object Storage & High-Throughput Segmentation on AWS

Open Interactive Vault Dashboard

1. Overview & Objectives

Problem Statement: Storing unencrypted files on public cloud providers exposes sensitive personal or institutional data to potential breaches, accidental public bucket misconfigurations, and regulatory non-compliance.

Primary Objective: Implement client-side/application-level file segmentation, authenticated AES-256-GCM encryption, private S3 cloud storage, and cryptographic file reconstruction. Keys are never exposed to cloud infrastructure.

3. Technical Implementation

File Segmentation

Files are streamed in binary chunks of 1 MiB (1,048,576 bytes) to optimize upload handling and prevent high RAM usage.

AES-256-GCM Encryption

Each block is encrypted independently using a cryptographically secure 256-bit key and unique 96-bit nonce with authenticated tags.

Integrity Verification

SHA-256 checksums are calculated during upload and verified byte-by-byte upon reconstruction during download.

CloudFront & S3 Hosting

S3 static site assets are served through CloudFront with Origin Access Control (OAC) and HTTPS redirection.

4. S3 Storage & Retrieval Workflow

  1. Upload: User uploads file → File is split into 1 MiB blocks → Unique 256-bit AES key generated → Blocks encrypted with unique nonces → Uploaded to files/{file_id}/blocks/*.enc → Manifest saved to files/{file_id}/manifest.json.
  2. Download: Manifest retrieved → Key loaded from local key store → Blocks retrieved in sequence → Decrypted and verified with AES-GCM → SHA-256 recalculated & matched → Streamed to user.

6. Limitations & Future Enhancements

  • Current version uses single-user local key management; future enhancements will integrate AWS KMS (Key Management Service).
  • Multi-user authentication and role-based access control (Cognito / JWT).
